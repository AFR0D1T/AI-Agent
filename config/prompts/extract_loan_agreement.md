Ты извлекаешь финансовые ковенанты из текста кредитного договора (раздел
«Статья 6 — Финансовые ковенанты», пункты вида 6.1, 6.2, 6.3).

Для **каждого** найденного пункта верни объект со следующими полями:

- **clause** — номер пункта ровно как в тексте (например `"6.1"`).
- **test_type** — тип проверки, один из:
  - `ratio` — коэффициент/отношение двух величин с лимитом (например
    (Налоги + Коммунальные расходы) / EBITDA ≤ X).
  - `absolute_cap` — абсолютный денежный потолок: сумма не должна превышать X.
  - `minimum_floor` — абсолютный денежный минимум: сумма не должна быть ниже X
    (например минимальная выручка).
  - `related_party_cap` — лимит именно на платежи связанным сторонам, если
    пункт явно ссылается на статус «связанная сторона» / «related party» —
    используй этот тип вместо общего `absolute_cap`.
- **threshold** — числовое значение порога из текста, без единиц измерения
  (например `1500000` или `0.30`).
- **currency** — код валюты порога (например `"USD"`), если порог — денежная
  сумма; `null`, если порог — безразмерный коэффициент.
- **raw_text** — дословная цитата пункта из договора (для трассируемости
  дальнейшего решения).
- **account_id** (одно значение на весь документ, не на пункт) — код счёта
  вида `ACC-XXXX`, к которому относится договор, если упомянут в тексте.

### Как описать, какие транзакции входят в расчёт

В реестре транзакций **нет колонки категории** — состав показателя (например
«Налоги + Коммунальные расходы» или «Выручка») определяется по ключевым
словам, которые должны встречаться в описании операции или названии
контрагента. Поэтому для `numerator`/`denominator` (только для `ratio`) и
`aggregate` (для остальных трёх типов) верни объект:

- **description_keywords** — список ключевых слов/фраз на английском (как в
  описаниях транзакций), по вхождению которых (без учёта регистра) операция
  включается в этот показатель. Например для «Налоги» — `["tax"]`, для
  «Коммунальные расходы» — `["electricity", "utility", "water"]`. Пустой
  список — не фильтровать по тексту (например если показатель определяется
  только знаком/related-party, см. ниже).
- **exclude_keywords** — ключевые слова, при наличии которых операция
  исключается, даже если совпала по `description_keywords`.
- **related_party_only** — `true`, только если показатель — это именно
  платежи связанным сторонам (обычно для `related_party_cap`, где сам тип уже
  подразумевает связанные стороны — в этом случае можно оставить `false`,
  фильтрацию по related-party код применит сам).
- **sign** — `"debit"` (только расходы, отрицательные суммы), `"credit"`
  (только поступления, положительные суммы) или `"any"` (не фильтровать по
  знаку). Например «Выручка» обычно `"credit"`, «Налоги»/«Коммуналка» —
  `"debit"`.

Если пункт — `ratio`, заполни и `numerator`, и `denominator` (`aggregate`
оставь `null`). Если пункт — `absolute_cap`/`minimum_floor`/
`related_party_cap`, заполни `aggregate` (`numerator`/`denominator` оставь
`null`).

Извлекай условия только из текста, который тебе передан целиком — не
пытайся сопоставлять его с другими версиями договора, это делает отдельный
шаг пайплайна. Если в тексте нет ни одного из пунктов 6.1–6.3 — верни пустой
список `covenants`, не придумывай пункты.

Отвечай строго в формате предоставленной JSON-схемы, без пояснений вне неё.
